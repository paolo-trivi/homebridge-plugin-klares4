# T0.3 — One validation point for the user config

## Config keys

None added, renamed or removed. The schema is unchanged; what changed is how the plugin reads it (see the table below).

## Changelog entries (2.3.0)

### Security
- `allowInsecureTls` is on only for the JSON value `true`. A hand-edited `"allowInsecureTls": "false"` (or `"true"`, `1`, ...) used to switch certificate verification **off**; it now keeps it on and logs which key was ignored. The same strictness applies to `exposePartialArmScenarios` (`"true"` and `1` do not expose arming scenarios) and to every other on/off option. (WS-09, PLAT-01)

### Changed
- Every boolean option is read the same way: an option whose default is `false` is active only for `true`, and one whose default is `true` is inactive only for `false`. Any other value (`"false"`, `0`, `1`, `"true"`, an object) is ignored, the safe default applies, and one warning at startup names the key and the type it received. (WS-09, PLAT-18)
- Numeric options are held to the limits declared in `config.schema.json`: a value that is not a number, not finite or not an integer where one is required falls back to the default; a value outside the range is moved to the nearest limit. A warning at startup lists each correction. `matterUnregisterTimeoutMs` is now held to its documented 500..30000 range, and an invalid `port` or `mqtt.port` falls back to the default port instead of being used. (WS-09, PLAT-18, TD-DOC-15)
- Configuration problems are reported once at startup, grouped in one warning, without ever printing the PIN, the MQTT password or the panel address. A `pin` that is neither a string nor a number is a clear error and the plugin does not start. (PLAT-18)
- The matterOverrides warning "hides N device(s) from Matter" is now logged when the first synchronization has finished and counts only devices the panel really reported. (MAT-10)
- The one remaining Italian log message ("Configurazione mancante: IP e PIN sono obbligatori") is now in English. (TD-DOC-15)

### Fixed
- `reconnectInterval: 0` or a negative value (hand-edited `config.json`) no longer makes the plugin reconnect hundreds of times per second; `heartbeatInterval: 0` no longer drops the connection at every tick. Both are raised to the schema minimum. The WebSocket client also keeps its defaults when an option is passed explicitly as `undefined`. (WS-09)
- `excludeZones`, `excludeOutputs`, `excludeSensors` and `excludeScenarios` accept what users write: numbers (`5`), strings with spaces (`" 5"`) and full device IDs (`"gate_5"`, `"light_5"`, `"zone_3"`, `"scenario_2"`, `"sensor_temp_1"`; the panel's own temperature sensors stay `sensor_system_temp_in` / `sensor_system_temp_out`). A value that is not a list is ignored with a warning instead of matching by substring or throwing; an entry that is not a device ID of that kind is dropped and named in the warning. The comparison stays exact. (PLAT-06)
- `matterOverrides`, `matterRecoveryRequests` and `customNames` in their legacy map form are validated like the array form: a `null`, a number or a non-string name no longer stops the platform from starting (`matterOverrides: { zone_1: null }`) or breaks the MQTT topics (`customNames` with a numeric value); the bad row is dropped and reported. A device whose ID is `constructor` or `__proto__` no longer picks up a name from the object prototype. (PLAT-10, MAT-09)
- Two `matterOverrides` rows for the same device are merged instead of the last one replacing the first (one row hides a device, another renames it: both apply); a conflict between the two is warned about and the last value wins. (MAT-10)
- After the first synchronization, one warning lists the `matterOverrides`, `matterRecoveryRequests` and `customNames` entries that match no device on the panel, with a "did you mean" hint when the ID is only a number (`1` instead of `zone_1`) or in capitals (`ZONE_1`). (MAT-10)

## Migration notes
- Values of the wrong type are no longer interpreted. If a boolean was written as text (`"true"`), a number as text (`"5000"`) or a list as a single string, the key now falls back to its default and the log says so at startup: fix the value in the plugin settings. Valid configurations behave exactly as before; nothing is renamed and no persisted data changes.
- If `allowInsecureTls` was a string and the panel's certificate is self-signed, the connection will now be refused (this is the intended behaviour): set it to `true` (the checkbox in the settings) to accept the certificate.
- Numeric values outside the schema limits are corrected (for example `maxSeconds: 3` becomes 5, `reconnectInterval: 0` becomes 1000).
- `platform.config` (read by accessories, MQTT bridge, KSA import) now carries the validated values, so a custom build reading it directly sees clamped numbers and clean lists. `platform.runtimeConfig` is the complete, non-optional form.

## Documentation notes
- The `telemetry` key is not handled here and keeps its current behaviour.
- Add to the config reference (README EN/IT, `docs/en|it`): on/off options need a real `true`/`false`; the limits below are enforced at runtime, not only by the settings form. The schema is unchanged, so no schema edit is needed for this task. The only schema-adjacent suggestion: `temperatureDefaults.step` is documented as 0.5 or 1 (an `enum` in the schema) and is now enforced as such.
- Troubleshooting page: the startup messages "Configuration: N value(s) ignored or adjusted ...", "Invalid configuration, pin: ..." and "Configuration: these entries match no device discovered on the panel ..." and how to fix them. Device ID forms: `zone_1`, `light_5`, `cover_7`, `gate_9`, `thermostat_18`, `scenario_2`, `sensor_temp_3` (in `matterOverrides`, `matterRecoveryRequests`, `customNames`); bare numbers, or full IDs, in the four `exclude*` lists.
- ARCHITECTURE: `platform/runtime-config.ts` (`resolveRuntimeConfig`) is the only place the raw Homebridge config is interpreted; `platform/runtime-config-limits.ts` holds the numeric limits table (a test compares it with `config.schema.json`); `config-values.ts` has the readers and the grouped warning collector; `exclusion-lists.ts`, `custom-names-config.ts` and `matter-override-config.ts` hold the list and per-device normalization; `override-reconciliation.ts` is the end-of-first-sync report. `Lares4Config` is the validated view (`platform.config`), `RawLares4Config` the input type.

### Runtime table: key, type, default, limits applied at runtime

Out of range: nearest limit, except where noted. Wrong type, NaN, Infinity or a non-integer for an integer key: the default (no default: the key is ignored) and a warning.

| Key | Type | Default | Applied at runtime |
|---|---|---|---|
| `ip` | string | none (required) | trimmed; a non-string is reported and counts as missing |
| `pin` | string or number | none (required) | a number becomes a string; any other type is an error (value never logged) |
| `port` | integer | 443 with `https`, 80 without | 1..65535, otherwise the default |
| `https` | boolean | `true` | off only for `false` |
| `allowInsecureTls` | boolean | `false` | on only for `true` |
| `sender` | string | `homebridge` | non-empty after trim |
| `debug` | boolean | `false` | on only for `true` |
| `logLevel` | integer | 1 | 0, 1 or 2; otherwise `debug: true` gives 2, else 1 |
| `maxSeconds` | integer | 30 | 5..300 |
| `reconnectInterval` | integer | 5000 | 1000..60000 |
| `heartbeatInterval` | integer | 30000 | 10000..300000 |
| `commandTimeoutMs` | integer | 8000 | 1000..30000 |
| `coverStepSize` | integer | 5 | 1..20 |
| `scenarioAutoOffDelay` | integer | 500 | 100..5000 |
| `devicesSummaryDelay` | integer | 2000 | 500..10000 |
| `exposePartialArmScenarios` | boolean | `false` | on only for `true` |
| `excludeZones` / `excludeOutputs` / `excludeSensors` / `excludeScenarios` | array of IDs | `[]` | entries: number, trimmed string or full device ID of that kind, normalized to the panel ID and compared exactly; a non-array is an empty list; invalid entries dropped |
| `matterExposure.zones` / `sensors` / `scenarios` / `lights` / `covers` / `gates` / `thermostats` | boolean | `true` | off only for `false` |
| `matterOverrides[]` | array of `{deviceId, name, exposed}` (legacy map accepted) | none | rows validated; same `deviceId` (exact, after trim) merged, last value wins on conflict |
| `matterRecoveryRequests[]` | array of `{deviceId, generation}` (legacy map accepted) | none | `generation` an integer of at least 1 |
| `matterUnregisterTimeoutMs` | integer | 3000 (unset: environment variable, then 3000) | 500..30000 |
| `customNames[]` | array of `{deviceId, name}` (legacy map accepted) | none | rows validated; names must be non-empty strings; lookups on own properties only |
| `temperatureDefaults.target` | number | 21 | 5..35 |
| `temperatureDefaults.min` | number | 10 | 5..20 |
| `temperatureDefaults.max` | number | 38 | 25..40 |
| `temperatureDefaults.step` | number | 0.5 | 0.5 or 1 |
| `domusThermostat.enabled` | boolean | `true` | off only for `false` |
| `domusThermostat.sensorFreshnessMs` | integer | 300000 | 30000..3600000 |
| `domusThermostat.manualPairs[]` / `manualCommandPairs[]` | arrays of objects | `[]` | rows need both IDs (string or integer); others dropped |
| `ksaImport.enabled` / `applyAtStartup` / `applyCustomNames` / `applyExclusionSuggestions` | boolean | `false` | on only for `true` |
| `ksaImport.applyDomusMappings` / `applyRoomMapping` | boolean | `true` | off only for `false` |
| `ksaImport.filePath` | string | none | a non-string is ignored |
| `mqtt.enabled` | boolean | `false` | on only for `true` |
| `mqtt.broker` / `username` / `password` / `clientId` | string | none | a non-string is ignored |
| `mqtt.port` | integer | none (taken from the broker URL) | 1..65535, otherwise ignored |
| `mqtt.topicPrefix` | string | `homebridge/klares4` | non-empty |
| `mqtt.qos` | integer | 1 | 0, 1 or 2 |
| `mqtt.retain` | boolean | `true` | off only for `false` |
| `roomMapping.enabled` | boolean | `false` | on only for `true` |
| `roomMapping.rooms[]` | array | `[]` | rooms need a `roomName` (kept as written: it is part of the topic); devices need a `deviceId` |
| `generateDebugFile` | boolean | `false` | on only for `true` |
| `debugCaptureDurationMs` | integer | 60000 | 10000..1800000 |
| `telemetry` | boolean | `true` | not handled here |
